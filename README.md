# Graph collections for QAOA and IQP analysis

NetworkX graph definitions and the adjacency-cospectral pairs used in Sammy Beasley's QAOA and IQP research. Graphs are stored as explicit Python vertex and edge lists. The original collection order and vertex labels are preserved.

## Python modules

| Module | Contents |
| --- | --- |
| `regular_graphs.py` | Access to 155,026 connected regular graphs in 22 collections. Explicit edges are organised by collection in `_graph_data/`. |
| `connected_graphs_4_to_7.py` | All 992 connected graphs on 4–7 vertices generated by Sammy Beasley, grouped by order. |
| `cospectral_pairs.py` | 10,486 saved regular-graph pairs and the studied 16-vertex Rook/Shrikhande pair. |
| `strongly_regular_graphs.py` | The 16-vertex pair and 70 larger strongly regular graphs retained as reference data. |
| `graph_families.py` | The circular/Mobius ladders, special pairs and other named families from the research notebooks. |

The graph modules require only NetworkX:

```bash
python -m pip install networkx
```

Run the examples from this repository, or add its directory to your Python path.

## Using the graphs

```python
from regular_graphs import get_graph, all_10v_4reg_graphs
from connected_graphs_4_to_7 import all_7v_connected_graphs
from cospectral_pairs import get_pairs, PAIR_INDICES

G = get_graph(10, 4, index=10)
print(G.number_of_nodes(), G.number_of_edges())

regular_collection = all_10v_4reg_graphs      # 59 NetworkX graphs
connected_collection = all_7v_connected_graphs  # 853 NetworkX graphs
G1, G2 = get_pairs("10v_4reg")[0]
print(PAIR_INDICES["10v_4reg"][0])           # (10, 20)
```

`get_graph` and `get_pairs` return fresh graphs. The named connected and strongly regular lists are ordinary mutable Python lists; use `G.copy()` when editing one of those graph instances.

Use `iter_graphs(n, degree)` to process a large regular collection one graph at a time. Only the requested edge-list parts are imported; importing `regular_graphs` alone does not construct all 155,026 graphs.

### Graph and pair indices

Indices in the Python API and `PAIR_INDICES` are **zero-based positions in the original lists**. For example, pair `(10, 20)` in `10v_4reg` selects list positions 10 and 20, corresponding to the original variables `G_10_4_11` and `G_10_4_21`. The original regular-graph display labels were one-based. These two conventions must not be interchanged.

Pair definitions refer to the regular graph definitions rather than duplicating their edge lists. Collections with no saved cospectral pairs are retained as empty lists. The 16-vertex strongly regular pair is available as `get_pairs("16v_srg")`.

## Connected graphs on 4–7 vertices

These collections were generated independently by Sammy Beasley and exported from the saved graph lists used in the notebooks. They contain all connected simple graphs of each order, with one representative per isomorphism class: 6 on four vertices, 21 on five, 112 on six and 853 on seven. Validation compares them with NetworkX's graph atlas up to isomorphism while preserving the project's original order and labelling.

## Metadata and validation

`data/provenance.json` records the original source filenames and checksums. The `data/` tables retain stable graph IDs, collection membership, original labels, pair indices and study status for joining existing analysis results. `graphs.csv` points to Python collection positions; it contains no encoded graph payloads. Graph identities preserve stored vertex order and are not isomorphism-canonical identifiers.

`graph_catalogue.load_collection(name)` remains available for existing notebooks. It returns `(label, graph)` entries with the source vertex labels. `graph_catalogue.load_graphs(ids)` returns graphs with vertices numbered in stored order for the analysis CLI.

Run the complete structural checks with:

```bash
python -m pip install -r requirements.txt
python validate.py
```

Validation checks the Python definitions against the stable catalogue identities, connected-graph completeness through seven vertices, strongly regular parameters, pair indices, adjacency spectra and file checksums.
